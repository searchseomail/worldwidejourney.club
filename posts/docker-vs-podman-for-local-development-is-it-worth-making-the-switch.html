Docker vs. Podman for Local Development: Is It Worth Making the Switch?

JungleJester
Topic Starter
Posted: 09.01.2025 15:41
I've been using Docker Desktop for my local development setup for years, but lately, I've been hearing a lot of buzz about Podman as a secure, daemonless alternative. Since my company recently updated its licensing policies, I'm seriously considering whether it's worth the friction to migrate my daily workflow over. For those of you who have made the switch for local dev, did you run into major issues with Docker Compose compatibility, volume mounts, or IDE integrations?

Replies (14)

VortexVagabond
Replied: 27.01.2025 06:46
I made the switch about six months ago for similar licensing reasons, and honestly, the transition was much smoother than I expected. `podman-compose` handles most standard compose files without a hitch, though you do have to alias `docker=podman` in your shell to keep your muscle memory working.
InfiniteIcon
Replied: 12.02.2025 04:12
Volume mounts can be a bit tricky on macOS due to SELinux and rootless permission mapping. If you're on Linux, it's a dream because it's truly daemonless, but Mac performance with osxfs alternatives still feels a bit behind Docker Desktop.

Replied: 11.03.2025 14:51

SilentStorm
Replied: 16.03.2025 13:24
JetBrains IDEs integrated with Podman pretty easily once I pointed them at the proper socket path (`/var/run/podman/podman.sock` or the user-specific equivalent). VS Code also has a decent Podman extension now that makes managing containers a breeze.
CosmicCoder
Replied: 11.04.2025 00:18
The biggest friction point for me was networking between containers. Docker Compose creates a default bridge network that sometimes behaves slightly differently under Podman, requiring explicit network declarations in the compose file.

Honestly, if your company forced the migration due to Docker Desktop licenses, it's totally worth the initial setup pain. Once you get past the first week of minor tweaks, not having that heavy daemon resource hog in the background is amazing.

To answer the Testcontainers question: yes, it works surprisingly well now! Podman provides a systemd service that emulates the Docker socket, so most tools that talk to the Docker socket work out-of-the-box if you export `DOCKER_HOST` correctly.
